**Date:** 2026-08-14

## Areas Discussed & Decisions

### 1. Admin Page Routing and Sidebar Visibility
- **Options Considered:**
  1. Nested in `/account/admin` with sidebar link visible only for `ADMIN_EMAIL`. Non-admin direct visits redirect to `/account` with error toast.
  2. Top-level `/admin` separate page and layout.
  3. Embedded directly inside `/account` main dashboard.
- **User Decision:**
  - Route `/account/admin` inside existing account layout.
  - Sidebar "Admin" tab rendered only when session email equals `ADMIN_EMAIL`.
  - Server-side authorization on every admin page and action; fail-closed if `ADMIN_EMAIL` is missing. Non-admins receive no data and redirect to `/account`; APIs return 403.

### 2. Uploads Manager Placement and Layout
- **Options Considered:**
  1. Dedicated `/account/uploads` tab in sidebar with 25 MB quota progress bar and thumbnail grid.
  2. Embedded inside `/account` as a collapsible section.
  3. Modal/Drawer library opened from image pickers.
- **User Decision:**
  - Dedicated `/account/uploads` route and sidebar tab.
  - Storage quota progress bar at top showing used vs remaining of 25 MB capacity.
  - Responsive thumbnail gallery with preview, filename/type, size, upload date, and delete button.
  - Strict server-side ownership enforcement: users can only see and delete their own uploads.
  - Clear empty, loading, error, and quota-exceeded states.

### 3. In-Use Image Deletion Safety & Cleanup
- **Options Considered:**
  1. Confirmation modal listing all active usages (avatar, background, link icons) with auto-cleanup of references in Page/User upon confirmed deletion.
  2. Confirmation modal with warning but leave references untouched.
  3. Hard block deletion until manually replaced on the page.
- **User Decision:**
  - Confirmation modal detailing every active reference (Avatar, Page Background, Link Icons).
  - On confirmed delete: verify ownership, remove S3 object and `Upload` record, and automatically clear/reset matching references in `User` and `Page` documents to avoid broken image URLs.
  - Coordinated error handling with immediate quota and UI refresh.

### 4. Allowlist Removal & Session Eviction Behavior
- **Options Considered:**
  1. Evict active sessions but preserve page & uploads.
  2. Complete destructive wipe of user data on allowlist removal.
  3. Allowlist-only removal without session eviction.
- **User Decision:**
  - Deleting an `AllowedUser` record immediately revokes/deletes all active sessions for that user in MongoDB, forcing immediate logout.
  - Preserve `Page` and `Upload` records (access revocation != data deletion); if re-added later, user data becomes accessible again.
  - Protected endpoints re-verify allowlist status server-side.
  - Permanent data deletion reserved as a separate, explicit admin workflow.
