**`lib/magicBytes.js`** — export `detectImageType(buffer)` returning either
`{ mime: 'image/jpeg'|'image/png'|'image/webp', ext: 'jpg'|'png'|'webp' }` or `null` when nothing
matches. Per D-14 no dependency is added — the `file-type` package is explicitly out.

Implementation constraints:
- Read at most the first 12 bytes. Return `null` immediately if `buffer.length < 12`.
- JPEG: bytes 0-2 equal `0xFF 0xD8 0xFF`.
- PNG: bytes 0-7 equal `0x89 0x50 0x4E 0x47 0x0D 0x0A 0x1A 0x0A`. Compare the full 8-byte signature,
  not the 4-byte short form.
- WEBP: bytes 0-3 are ASCII `RIFF` AND bytes 8-11 are ASCII `WEBP`. Both halves are required — a
  buffer with `RIFF` and no `WEBP` must return `null`, because `RIFF` alone is also WAV and AVI.
- The client's declared `Content-Type` is not a parameter of this function at all. That is the point of
  D-14: there is nothing to spoof.
- Nothing else is accepted. SVG (D-13: `public-read` objects make an SVG with `<script>` stored XSS) and
  GIF both fall through to `null`.

**`lib/username.js`** — export `validateUsername(name)` returning `{ ok: true }` or
`{ ok: false, error: '<user-facing reason>' }`, plus a named export `RESERVED_USERNAMES` (a `Set`).
This is a plain module, NOT inside a `'use server'` file — D-24 requires one shared source of truth and
the claim form is a client component, so it cannot import from a server-action module.

Rules, checked in this order so the error message is the most specific one:
1. Missing / non-string / empty after trim → `error: 'Username is required'`
2. Length < 3 or > 30 (D-22) → `error: 'Username must be 3-30 characters'`
3. Fails `/^[a-z0-9_-]+$/` (D-21) → `error: 'Username can only contain lowercase letters, numbers, hyphens and underscores'`
4. Present in `RESERVED_USERNAMES` (D-23) → `error: 'That username is reserved'`

The function must NOT lowercase its input — it validates the already-lowercased value the caller
passes (`grabusername.js:11` lowercases). An uppercase input is a charset failure, which is what the
SEC-07 signal `Bad.Name` / `emoji` cases expect.

`RESERVED_USERNAMES` resolves RESEARCH.md Planner Decision Point 6. It is a superset of the real
`app/` route segments enumerated from disk — `api`, `account`, `analytics`, `about`, `login` — plus the
curated ~30-word admin-ish set D-23 names: `admin`, `administrator`, `root`, `superuser`, `support`,
`help`, `contact`, `settings`, `config`, `privacy`, `terms`, `legal`, `security`, `billing`, `signup`,
`signin`, `signout`, `logout`, `register`, `auth`, `oauth`, `dashboard`, `profile`, `user`, `users`,
`me`, `static`, `public`, `assets`, `favicon`, `robots`, `sitemap`, `null`, `undefined`, `true`,
`false`, `test`, `new`, `edit`, `delete`. No profanity list (D-23: always incomplete, and abuse
reporting is already a v2 requirement). Add a `ponytail:` comment noting that adding a new top-level
`app/` route later requires adding it here, since a collision with a claimed username is unrecoverable.

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| uploaded bytes → `detectImageType` | fully attacker-controlled buffer; the function must not trust length or any declared type |
| claim form input → `validateUsername` | attacker-controlled string that becomes a public URL path segment |
| local shell → live DB/S3 | the verification harness reads production state and writes test uploads |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-02-01 | Spoofing | `detectImageType` | mitigate | Signature comparison only; the declared `Content-Type` is not a parameter. WEBP requires both `RIFF` and `WEBP` so WAV/AVI cannot masquerade |
| T-02-02 | Tampering | `validateUsername` reserved list | mitigate | Reserved set is a superset of every real `app/` route segment enumerated from disk, so a claimed username cannot shadow a route |
| T-02-03 | Information Disclosure | `validateUsername` error strings | accept | Errors state the rule, not whether a name exists; uniqueness is a separate check in plan 01-06 |
| T-02-04 | Denial of Service | `detectImageType` on a huge buffer | mitigate | Reads at most 12 bytes and returns early below that length; size gate fires before it in plan 01-04 |
| T-02-05 | Information Disclosure | `VERIFY_SESSION_COOKIE` in the environment | accept | Local-only developer harness; the cookie is never written to a file or committed |
| T-02-SC | Tampering | npm installs | mitigate | Zero new dependencies (D-14 forbids `file-type`; VALIDATION.md forbids a test framework). `package.json` must be byte-identical after this plan |
</threat_model>
