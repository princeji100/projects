<objective>
Harden `/api/click`. It is the only public write in the app — visitors are supposed to reach it
unauthenticated — and all eleven of its lines are unguarded. It has TWO distinct defects, verified
experimentally on node v24, and a fix that addresses only the obvious one leaves the worse one live:

- `atob('!!!')` THROWS `InvalidCharacterError`, so a malformed param 500s. This is the bug SEC-08 names.
- `atob(null)` does NOT throw. A missing `url` param stringifies to `"null"`, decodes to `"ée"`, and the
  handler writes `Event { type:'click', url:'ée', page:null }` and returns HTTP **200**. Undetectable
  garbage in the analytics collection — arguably worse than the 500 because nothing surfaces it.

Purpose: no stranger can 500 the endpoint or write rows the analytics page will later report on.
Output: a hardened `app/api/click/route.js`.
</objective>

<interfaces>
From plan 01-03: `lib/rateLimit.js` exports `checkRateLimit('click', key)` → `{ allowed, retryAfter }` and
`rateLimitKey('click', session, req)`. `LIMITS.click` is 60 per 60,000 ms. With no session available here,
`rateLimitKey` derives the identifier from the FIRST `x-forwarded-for` entry, falling back to `'unknown'`.

Verified `atob` behaviour on node v24 (`atob` is a global, no import needed):
  `null`                   → `"ée"`            no throw
  `""`                     → `""`              no throw
  `"abc"`                  → `"i·"`            no throw
  `"!!!"`                  → THROWS InvalidCharacterError
  `"aHR0cHM6Ly94LmNvbQ=="` → `"https://x.com"`
`atob` accepts plenty of junk without complaint, so a try/catch alone does not establish validity.
Round-tripping — `btoa(atob(x)) === x` — is the reliable check.

`Page.uri` is `unique: true` (`models/Page.js:5`) so it is indexed; the existence check is one indexed read
per click.

There is no `GET` handler in this file and no separate view-event route, so this single `POST` is the whole
public write surface.
</interfaces>

  <action>
Rewrite the handler. Order the checks so the cheapest run first and NOTHING writes an `Event` unless every
check passed.

1. **Rate limit first (SEC-05, D-18, D-19).** This endpoint is unauthenticated and public, so it is the one
   surface where an unbounded request rate is reachable by anyone. `const key = rateLimitKey('click', null,
   req)` then `checkRateLimit('click', key)`. When not allowed return `Response.json({ error: 'Too many
   requests' }, { status: 429, headers: { 'Retry-After': String(retryAfter) } })`. Route handlers can set
   headers, so the full D-20 shape applies here (unlike the server actions in plans 01-06 and 01-08).
   Placing the limiter first means a flood costs one Mongo upsert rather than an upsert plus two reads.

2. **Presence, BEFORE decoding (D-26, bug 2).** Read `searchParams.get('url')` and
   `searchParams.get('page')` into locals. If either is `null` or an empty string, return
   `Response.json({ error: 'Missing parameters' }, { status: 400 })`. This must happen before `atob` is
   called at all — `atob(null)` silently succeeds and is precisely how the garbage-row-with-200 bug
   happens. Do not rely on the try/catch to catch it; it never throws.

3. **Decode with validation (D-26, bug 1).** Wrap the decode in try/catch AND verify the round trip:
   decode with `atob(raw)`, then require `btoa(decoded) === raw`. Fail either the throw or the round-trip
   check → `Response.json({ error: 'Invalid url parameter' }, { status: 400 })`. The round trip is what
   makes this reliable: `atob('abc')` returns junk without throwing, so a try/catch alone accepts it.

4. **Page existence (D-27).** `await connectToDatabase()` then `const exists = await Page.findOne({ uri:
   page }).select('_id').lean()`. If not found, return `Response.json({ error: 'Unknown page' }, { status:
   400 })`. Without this, any stranger can inflate the `Event` collection with arbitrary page names, which
   pollutes exactly the data Phase 5's analytics will report on. Use `.select('_id').lean()` — only
   existence matters, so do not pull the whole document.

5. **Then, and only then**, `await Event.create({ type: 'click', url: decoded, page })` and
   `return Response.json(true)` — keeping the existing `true` response body so nothing downstream breaks.

Every failure path must return before any `Event.create`. The acceptance criteria assert the `events` count
is unchanged across all failure cases, because a status-code-only check would pass on an implementation
that returns 400 after already writing the row.

Do NOT add a `GET` handler and do NOT touch view-event recording — that is `app/(page)/[uri]/page.js:35`
and is Phase 2's FIX-04.

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-07-01 | Denial of Service | unguarded `atob` throwing a 500 on `?url=!!!` | mitigate | try/catch around the decode returning 400 |
| T-07-02 | Tampering | missing `url` writing a garbage Event with HTTP 200 | mitigate | Presence and non-empty check BEFORE `atob` is called — `atob(null)` never throws, so the try/catch cannot catch this |
| T-07-03 | Tampering | junk that `atob` accepts silently (`"abc"`) | mitigate | `btoa(atob(x)) === x` round-trip validation |
| T-07-04 | Tampering | Events written against arbitrary non-existent page names | mitigate | `Page.findOne({ uri: page })` existence check before `Event.create`, returning 400 (D-27) |
