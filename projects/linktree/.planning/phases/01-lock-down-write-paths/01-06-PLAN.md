<objective>
Gate the username claim. Today `action/grabusername.js` validates nothing beyond presence and uniqueness,
so `api`, a single character, `Bad.Name`, or an emoji all become public URLs. A claimed name that collides
with a real `app/` route is unrecoverable, which is why the reserved list matters more than the charset.

The claim is also the username-enumeration path, so D-19 gives it the strictest limit in the phase:
5 per hour.

Purpose: every claimed username is a safe, unambiguous URL segment, refused with a visible reason when it
is not.
Output: a gated `action/grabusername.js` with a consistent return contract.
</objective>

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| claim form input → a public URL path segment | the string becomes `/<username>` and is served to the internet |
| claim action → the `pages` collection | an unbounded claim rate is a username-enumeration and squatting channel |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-06-01 | Spoofing | claiming a username that shadows a real route (`api`, `login`, `account`) | mitigate | `RESERVED_USERNAMES` is a superset of every `app/` route segment enumerated from disk; a collision would be unrecoverable |
| T-06-02 | Tampering | path-traversal or delimiter characters in a URL segment | mitigate | `^[a-z0-9_-]+$` rejects `/`, `.`, `%` and whitespace; dots are excluded per D-21 because they read as file extensions |
| T-06-03 | Information Disclosure | username enumeration via repeated claim attempts | mitigate | 5 per hour per session email — the strictest limit in the phase, deliberately so per D-19 |
| T-06-04 | Elevation of Privilege | squatting 1-2 character premium names | mitigate | Minimum length 3 (D-22) |
| T-06-05 | Repudiation | an unauthenticated caller reaching the claim path | mitigate | The session check runs first and returns before any database access |
| T-06-06 | Information Disclosure | the uniqueness error confirming a name is taken | accept | Inherent to any claim flow — the user must be told the name is unavailable, and the 5/hour limit bounds how fast the space can be probed |
| T-06-07 | Tampering | the action and the form disagreeing on the rules | mitigate | One shared `lib/username.js`; the acceptance criteria assert no rule is duplicated in the action |
| T-06-SC | Tampering | npm installs | mitigate | Zero new dependencies; validation is a hand-written regex plus a Set |
</threat_model>
